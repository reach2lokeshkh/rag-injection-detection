# Detecting Indirect (Retrieved-Content) Prompt Injection in RAG

A small, fully reproducible experiment that measures how well three detector
designs catch **indirect prompt injection** — malicious instructions hidden
inside *retrieved documents* in a retrieval-augmented generation (RAG) system,
rather than in the user's own prompt.

This is a deliberately different threat model from screening a user's prompt.
In RAG, the application fetches documents and pastes their text into the model's
context. An attacker who can plant a poisoned document in the corpus can embed
instructions there; when that passage is retrieved, the model may follow the
attacker's instructions even though the user's prompt was completely benign.
The malicious text is surrounded by legitimate document content and is phrased
to look like part of a document, not like a command — which is what makes it
hard to detect.

## What it compares

Three detectors, all operating on the **retrieved passage text**:

1. **Rules only** — regular-expression / keyword matching for known injection
   phrasings.
2. **Machine-learning only** — TF-IDF (unigram + bigram) features with a
   logistic-regression classifier over passage text.
3. **Hybrid** — flags a passage if *either* the rules or the classifier fire.

## Why the split is technique-disjoint (the important part)

A naive random split of a synthetic corpus produces meaningless, near-perfect
scores because the classifier simply memorizes the injected strings. To measure
something honest — generalization to attack styles never seen before — this
experiment uses a **technique-disjoint** split:

- **Training** contains benign passages plus poisoned passages that use only
  the *seen* techniques (imperative override, fake system notice, tool-call
  abuse, plain-language exfiltration, character obfuscation).
- **Test** contains benign passages, some seen-technique poison, and — crucially
  — poison built from **novel** techniques that never appear in training
  (benign-vocabulary redirection, plain-language role framing, markup-hidden
  instructions).

The corpus is also made adversarially realistic: benign passages include
security-adjacent text (passwords, API keys, system notices, tool names, HTML
comments) so that a naive keyword rule false-positives on legitimate content.

## Results (seed = 42)

Measured on the held-out test set. Values are reproduced by running the script;
they are not hand-written.

**All held-out test passages**

| Detector | Precision | Recall | F1 | False-Positive Rate |
|---|---|---|---|---|
| Rules only | 0.614 | 0.514 | 0.560 | 0.323 |
| Machine-learning only | 1.000 | 0.549 | 0.708 | 0.000 |
| Hybrid | 0.690 | 0.720 | 0.705 | 0.323 |

**Novel (never-trained) techniques only**

| Detector | Precision | Recall | F1 | False-Positive Rate |
|---|---|---|---|---|
| Rules only | 0.369 | 0.377 | 0.373 | 0.323 |
| Machine-learning only | 1.000 | 0.097 | 0.177 | 0.000 |
| Hybrid | 0.405 | 0.440 | 0.422 | 0.323 |

**Takeaway.** Fixed rules cannot match phrasings they were never written for, so
their recall collapses on novel techniques. The classifier is precise but its
recall degrades sharply on genuinely unseen attack styles (memorization, not
understanding). The hybrid keeps the highest recall — the metric that matters
when one missed poisoned passage can hijack the answer — but even it misses more
than half of novel injections. The layered-defense principle carries over to the
retrieved-content layer, yet **no single layer is sufficient against novel
attacks**, and detection must run on documents at ingestion/retrieval time.

## Reproduce

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run_rag_injection_experiment.py
```

Outputs are written to `results/`:

- `rag_injection_metrics.json` — full metrics, including confusion-matrix counts.
- `rag_injection_results_table.md` — the tables above.

## Notes on scope and honesty

- The corpus is **synthetic and generated by the script**; it is not the
  `deepset` direct-prompt injection benchmark used in the companion
  direct-injection study. The two experiments are intentionally on different
  data and different threat models.
- All numbers come from a single seeded run and are fully reproducible. Nothing
  in this repository is hand-tuned to look better than it measures.
